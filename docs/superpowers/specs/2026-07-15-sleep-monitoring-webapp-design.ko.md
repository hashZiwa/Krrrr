# 수면 모니터링 웹앱 설계

## 목표

IoT 플랫폼에서 수집된 수면 센서 데이터를 사용자가 확인하고 모니터링할 수 있는 풀스택 웹 서비스를 만든다. 첫 구현에서는 생성된 mock 데이터를 사용하지만, 이후 실제 IoT 플랫폼 연동, 분석 기능, 플랫폼 업로드 기능을 쉽게 추가할 수 있도록 구조를 설계한다.

## 범위

초기 제품은 하나의 집중된 대시보드를 제공한다.

- 최근 2시간 수면 세션을 보여준다.
- 5분 간격의 mock 샘플 데이터를 생성한다.
- 수면 단계 샘플을 사각 펄스 또는 계단형 그래프로 표시한다.
- 호흡 샘플을 꺾은선 그래프로 표시한다.
- 차트 모델은 가변 길이 세션을 지원해야 하며, 실제 세션은 대략 10시간 이상까지 들어올 수 있다고 전제한다.
- 긴 세션에서는 사용자가 그래프를 좌우로 드래그하며 이동할 수 있고, 두 그래프는 같은 시간 구간을 함께 바라보도록 한다.
- 그래프 스타일과 레이아웃은 자주 바뀔 가능성이 있으므로, 차트 구현은 수정하기 쉬운 형태로 유지한다.

초기 제품에는 인증, 영구 저장소, 과거 세션 탐색, 실제 IoT 인증 정보, 업로드 워크플로는 포함하지 않는다. 다만 이런 기능은 이후 추가될 수 있으므로, 명확한 모듈 경계를 통해 확장 가능성을 확보한다.

## 권장 기술 스택

- Frontend: React, Vite, TypeScript
- Server: Express, TypeScript
- Charts: Recharts
- Styling: 디자인 토큰과 컴포넌트별 클래스명을 사용하는 로컬 CSS 파일

React와 Vite는 빠른 UI 개발 환경을 제공한다. Express는 작지만 명확한 API 계층을 제공하므로, 이후 IoT 플랫폼 클라이언트, 분석 서비스, 저장소 어댑터를 붙이기 좋다. Recharts는 계단형 그래프와 일반 꺾은선 그래프를 모두 지원하면서도 차트 설정을 읽기 쉽게 유지할 수 있다.

## 서버 아키텍처

서버는 이후 실제 운영 API 계약과 유사한 형태의 API를 제공한다.

- `GET /api/sleep-sessions/latest`

이 엔드포인트는 최신 수면 세션 하나의 메타데이터, 원본 샘플, 가벼운 요약 값을 반환한다. 초기 구현은 mock provider를 사용하지만, 라우트 핸들러가 직접 데이터를 생성하지 않고 provider/service 인터페이스에 의존하도록 만든다.

권장 서버 모듈:

- `server/src/index.ts`: Express 앱 시작점과 미들웨어 설정.
- `server/src/routes/sleepSessions.ts`: API 라우트 정의.
- `server/src/services/sleepSessionService.ts`: 세션 조회와 요약 계산 흐름 조정.
- `server/src/providers/mockSleepDataProvider.ts`: mock 샘플 데이터 생성.
- `server/src/models/sleep.ts`: 서버 측 공유 데이터 타입.
- `server/src/utils/time.ts`: 타임스탬프 포맷과 샘플 간격 관련 유틸리티.

이후 추가 가능한 provider/service 모듈:

- `iotSleepDataProvider`: 실제 IoT 플랫폼에서 데이터를 가져온다.
- `sleepAnalysisService`: 수면 품질, 무호흡 의심, 뒤척임 빈도, 깊은 수면 비율을 계산한다.
- `platformUploadService`: 파생 이벤트나 주석 데이터를 IoT 플랫폼에 다시 업로드한다.

## 데이터 모델

원본 센서 샘플은 공통적으로 단순한 형태를 가진다.

```ts
type SensorSample = {
  measuredAt: string; // yyyyMMddHHmmss
  value: number;
};
```

두 신호는 값의 의미가 다르므로, 세션 응답에서는 배열을 분리한다.

```ts
type SleepSessionResponse = {
  id: string;
  startedAt: string;
  endedAt: string;
  intervalMinutes: number;
  sleepStageSamples: SensorSample[];
  breathingSamples: SensorSample[];
  summary: {
    averageBreathingRate: number | null;
    movementCount: number;
    apneaRecognitionFailureCount: number;
    deepSleepRatio: number;
  };
};
```

수면 단계 값:

- `0`: 얕은 수면 또는 각성에 가까운 단계
- `1`: 중간 단계
- `2`: 더 깊은 수면 단계

호흡 값:

- `-1`: 뒤척임 또는 움직임 신호
- `0`: 무호흡증 인식 실패
- 양의 정수: 분당 호흡 횟수

평균 호흡 수치를 계산할 때는 0 이하의 호흡 값을 제외한다.

## Mock 데이터

첫 mock provider는 각 신호마다 25개의 샘플을 생성한다. 2시간 구간에서 5분마다 하나의 샘플을 만들며, 시작 시각과 종료 시각을 모두 포함한다. 이 2시간 데이터는 초기 설계와 그래프 동작을 확인하기 위한 임시 데이터일 뿐이며, 실제 운영 세션 길이로 간주하지 않는다.

차트와 API 설계는 훨씬 긴 세션을 허용해야 한다. 실제 세션은 대략 10시간 분량의 샘플을 포함할 수 있고, 이후 데이터 길이는 사용자, 장치, 수면 시간, 플랫폼 전달 방식에 따라 더 달라질 수 있다.

재현성을 위해 시작 시각은 고정할 수 있다. 첫 값으로는 `20260714230000`을 사용하면 좋으며, 이는 23:00부터 01:00까지의 데이터를 만든다. 생성되는 시퀀스는 그럴듯한 변화를 포함해야 한다.

- 수면 단계는 처음에는 얕게 시작하고, 중간에는 더 깊은 수면에 도달한 뒤, 끝으로 갈수록 다시 얕아진다.
- 호흡 값은 대부분 성인 수면 중 현실적인 범위에 머물며, 소수의 `-1` 및 `0` 이벤트를 포함한다.

Mock 데이터는 요청마다 달라지는 무작위 데이터가 아니라 결정적인 데이터여야 한다. 그래야 UI를 설계하고 조정하는 동안 화면이 안정적으로 유지된다.

## 프론트엔드 아키텍처

프론트엔드는 Express API에서 최신 세션을 가져와 간결한 대시보드로 렌더링한다.

권장 프론트엔드 모듈:

- `client/src/App.tsx`: 대시보드 구성.
- `client/src/api/sleepApi.ts`: API 호출과 응답 타입.
- `client/src/types/sleep.ts`: 프론트엔드 데이터 계약.
- `client/src/data/chartTransforms.ts`: 타임스탬프와 차트 데이터 변환.
- `client/src/data/timeWindow.ts`: 긴 세션을 보기 위한 표시 시간 구간 계산.
- `client/src/charts/chartConfig.ts`: 색상, 라벨, 축 동작, tooltip 포맷.
- `client/src/charts/SleepStageChart.tsx`: 계단형 수면 단계 그래프.
- `client/src/charts/BreathingChart.tsx`: 호흡 꺾은선 그래프.
- `client/src/components/TimeWindowController.tsx`: 긴 세션에서 좌우 드래그 또는 범위 조절을 담당하는 공통 컨트롤.
- `client/src/components/SummaryMetric.tsx`: 간결한 지표 표시 컴포넌트.
- `client/src/styles.css`: 시각 시스템과 레이아웃.

차트 컴포넌트는 의도적으로 얇게 유지한다. 변환된 데이터를 전달받고, 시각적 선택은 `chartConfig`에서 읽도록 만들어 향후 그래프 변경 대부분이 설정 파일이나 변환 파일에서 이뤄지게 한다.

두 차트는 하나의 표시 시간 구간 상태를 공유해야 한다. UI는 가독성을 위해 기본적으로 2시간 구간을 보여줄 수 있지만, 실제 세션 데이터는 더 길 수 있다. 좌우 드래그 제스처와 필요하다면 작은 범위 조절 컨트롤은 두 차트의 표시 시간 범위를 함께 변경해야 한다. 이렇게 하면 같은 수면 세션을 모니터링하는 두 그래프가 서로 다른 시간대를 보여주는 일을 피할 수 있다.

## UI 디자인 방향

첫 화면은 마케팅 페이지가 아니라 명확한 모니터링 대시보드처럼 느껴져야 한다. 훑어보기 쉬운 구조, 차분한 대비, 읽기 쉬운 그래프를 우선한다.

레이아웃:

- 상단 바에는 서비스명과 세션 측정 구간을 표시한다.
- 작은 요약 행에는 평균 호흡수, 뒤척임 횟수, 무호흡 인식 실패 횟수, 깊은 수면 비율을 표시한다.
- 좁은 화면에서는 두 그래프 패널을 세로로 쌓고, 넓은 화면에서는 공간에 맞게 명확하게 배치한다.

시각 방향:

- 어두운 잉크색 텍스트, 부드러운 오프화이트 배경, 차분한 청록 계열 수면 강조색, 특수 호흡 이벤트를 위한 따뜻한 경고색을 사용하는 조용한 임상적 팔레트를 사용한다.
- 카드 표면은 개별 대시보드 패널에만 절제해서 사용한다.
- 라벨은 간결하게, 축 포맷은 명확하게 유지한다.
- 장식적인 hero 섹션, 과도한 문구, 관련 없는 시각 요소는 피한다.

## 차트 동작

수면 단계 그래프:

- 사각 펄스 느낌을 만들기 위해 계단형 선 또는 영역 스타일을 사용한다.
- Y축 범위는 `[0, 2]`로 고정한다.
- X축 범위는 2시간으로 고정하지 않고, 공유 표시 시간 구간 상태가 제어한다.
- 0, 1, 2는 원시 숫자만 표시하지 않고 단계 라벨로 보여준다.
- Tooltip에는 사람이 읽기 쉬운 시간과 단계 라벨을 표시한다.

호흡 그래프:

- 양의 호흡 값은 일반 꺾은선 그래프로 표시한다.
- X축 범위는 수면 단계 그래프와 같은 공유 표시 시간 구간 상태가 제어한다.
- `-1`과 `0`은 기준선 위의 점 또는 강조 마커처럼 보이도록 남겨둔다.
- Tooltip은 `-1`을 뒤척임, `0`을 무호흡 인식 실패로 설명한다.
- 평균 호흡 요약에서는 `-1`과 `0`을 제외한다.

긴 세션 탐색:

- `yyyyMMddHHmmss` 타임스탬프는 차트에 사용하기 전에 숫자 기반 시간 값으로 변환한다.
- 현재 세션의 전체 데이터는 유지하되, 차트에는 현재 표시 시간 구간에 해당하는 데이터만 렌더링한다.
- Mock UI의 기본 표시 범위는 2시간으로 둘 수 있지만, 전체 도메인은 `startedAt`과 `endedAt`에서 가져온다.
- 좌우 드래그는 표시 시간 구간을 앞뒤로 이동시키되, 전체 세션 범위를 벗어나지 않도록 제한한다.
- Recharts의 brush 같은 라이브러리 기능을 사용하더라도 `TimeWindowController` 경계 뒤에 감싸서, 이후 차트 컴포넌트를 크게 고치지 않고 교체할 수 있게 한다.

## 오류 및 로딩 상태

프론트엔드는 기본 상태를 포함해야 한다.

- Loading: 간단한 대시보드 스켈레톤 또는 "Loading sleep data" 같은 짧은 메시지.
- Error: 수면 데이터를 불러올 수 없다는 명확한 메시지.
- Empty data: 사용 가능한 수면 세션이 없다는 메시지.

서버는 예상치 못한 실패에 대해 구조화된 JSON 오류를 반환해야 한다. 첫 mock 엔드포인트는 안정적으로 동작할 것으로 예상되지만, 응답 형태를 명확히 해두면 이후 IoT 연동 실패를 처리하기 쉬워진다.

## 테스트 및 검증

초기 검증에는 다음이 포함되어야 한다.

- 서버와 클라이언트의 타입 검사.
- 서버와 프론트엔드의 로컬 실행 성공 확인.
- 브라우저에서 두 그래프가 렌더링되는지, 타임스탬프가 읽기 쉬운지, 요약 값이 mock 데이터 의미와 일치하는지 수동 확인.

향후 유용한 테스트:

- Mock 데이터 생성 개수와 타임스탬프 간격에 대한 단위 테스트.
- 특히 `-1`과 `0` 처리와 관련된 요약 계산 단위 테스트.
- 차트 변환 함수에 대한 컴포넌트 또는 단위 테스트.

## 구현 메모

`client`와 `server` 폴더를 분리한 monorepo 스타일 구조를 사용한다. 루트 `package.json`은 양쪽 설치, 개발 실행, 빌드를 위한 편의 스크립트를 제공할 수 있다.

당장은 API 응답 타입을 클라이언트와 서버에 각각 맞춰 유지한다. 프로젝트가 커지면 shared package 또는 schema validation 계층을 도입한다.
